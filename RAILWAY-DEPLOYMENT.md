# 🚂 Railway Deployment Guide - WhaSales AI

Complete guide for deploying to Railway with post-deployment setup.

---

## 🎯 Why Railway?

Railway is perfect for this app because:
- ✅ Supports persistent WhatsApp sessions (not serverless)
- ✅ Easy MySQL database integration
- ✅ Simple environment variable management
- ✅ Automatic deployments from GitHub
- ✅ Built-in cron jobs (optional)

## 📋 Pre-Deployment Checklist

### 1. Generate Security Secrets

Run these locally and save the outputs:

```bash
# Generate all secrets at once
echo "NEXTAUTH_SECRET=$(openssl rand -base64 32)"
echo "CRON_SECRET=$(openssl rand -base64 32)"
echo "CSRF_SECRET=$(openssl rand -base64 32)"
```

### 2. Set Up Upstash Redis (Free)

1. Go to https://upstash.com
2. Sign up (GitHub OAuth is easiest)
3. Click "Create Database"
4. Choose region closest to your users
5. Copy **REST URL** and **REST Token**

### 3. Prepare Stripe Configuration

You'll need:
- Stripe Secret Key (`sk_live_...`)
- Stripe Publishable Key (`pk_live_...`)
- 9 Stripe Price IDs (one for each plan)

## 🚀 Railway Deployment Steps

### Step 1: Create New Project

1. Go to https://railway.app
2. Click "Start a New Project"
3. Choose "Deploy from GitHub repo"
4. Select your `Whatsapp-AI-Support-Agent` repository
5. Railway will auto-detect Next.js

### Step 2: Add MySQL Database

1. In your Railway project, click "+ New"
2. Select "Database" → "Add MySQL"
3. Railway will create a MySQL instance
4. It will auto-generate `DATABASE_URL` variable

### Step 3: Configure Environment Variables

Click on your web service → "Variables" tab → "RAW Editor"

Paste this and fill in your values:

```env
# Database (Auto-generated by Railway - DO NOT CHANGE)
DATABASE_URL=${{MySQL.DATABASE_URL}}?connection_limit=50&pool_timeout=20

# Node Environment
NODE_ENV=production

# OpenAI
OPENAI_API_KEY=sk-proj-your-key-here

# NextAuth (Use generated secrets from Pre-Deployment step)
NEXTAUTH_SECRET=your-generated-secret-32-chars
NEXTAUTH_URL=https://your-app.up.railway.app

# Stripe
STRIPE_SECRET_KEY=sk_live_your-key
STRIPE_PUBLISHABLE_KEY=pk_live_your-key
STRIPE_WEBHOOK_SECRET=whsec_your-webhook-secret

# Stripe Price IDs (Get from Stripe Dashboard)
STRIPE_PRICE_STARTER_MONTHLY=price_xxx
STRIPE_PRICE_STARTER_YEARLY=price_xxx
STRIPE_PRICE_PRO_MONTHLY=price_xxx
STRIPE_PRICE_PRO_YEARLY=price_xxx
STRIPE_PRICE_BUSINESS_MONTHLY=price_xxx
STRIPE_PRICE_BUSINESS_YEARLY=price_xxx
STRIPE_PRICE_LIFETIME_STARTER=price_xxx
STRIPE_PRICE_LIFETIME_PRO=price_xxx
STRIPE_PRICE_LIFETIME_BUSINESS=price_xxx

# Security Secrets (Use generated secrets from Pre-Deployment step)
CRON_SECRET=your-generated-secret-32-chars
CSRF_SECRET=your-generated-secret-32-chars

# Redis - Upstash (From Pre-Deployment step 2)
UPSTASH_REDIS_REST_URL=https://your-redis.upstash.io
UPSTASH_REDIS_REST_TOKEN=your-token-here

# Email (Optional - for verification emails)
EMAIL_SERVER_HOST=smtp.gmail.com
EMAIL_SERVER_PORT=587
EMAIL_SERVER_USER=your-email@gmail.com
EMAIL_SERVER_PASSWORD=your-app-password
EMAIL_FROM=noreply@yourdomain.com

# Admin Settings
ADMIN_CREATION_DISABLED=false
```

**Important Notes:**
- Replace `${{MySQL.DATABASE_URL}}` with the actual DATABASE_URL Railway provides
- The `?connection_limit=50&pool_timeout=20` at the end is important for performance
- Don't forget to add your actual domain to `NEXTAUTH_URL` after deployment

### Step 4: Update Build Settings (Optional)

Railway auto-detects Next.js, but if needed:

1. Go to Settings → "Build & Deploy"
2. Build Command: `npm install && npm run build`
3. Start Command: `npm start`

### Step 5: Deploy!

1. Click "Deploy"
2. Railway will:
   - ✅ Clone your repository
   - ✅ Install dependencies (including `@upstash/redis`)
   - ✅ Build Next.js app
   - ✅ Start the server

Wait 2-3 minutes for first deployment.

## 🔧 Post-Deployment Setup (CRITICAL!)

### Step 1: Run Prisma Migrations

**Railway CLI Method (Recommended):**

```bash
# Install Railway CLI
npm i -g @railway/cli

# Login to Railway
railway login

# Link to your project
railway link

# Run Prisma migration
railway run npx prisma generate
railway run npx prisma db push
```

**Alternative: Railway Dashboard**

1. Go to your web service → "Settings" → "Deploy"
2. Add a "One-off Command":
   ```bash
   npx prisma generate && npx prisma db push
   ```
3. This will run once and create all tables with indexes

**Verify Database:**

```bash
# Check tables were created
railway run npx prisma studio
```

This opens Prisma Studio to view your database.

### Step 2: Update NEXTAUTH_URL

1. Copy your Railway deployment URL (e.g., `https://whatsapp-ai-production.up.railway.app`)
2. Go to Variables → Edit `NEXTAUTH_URL`
3. Update to your actual URL
4. Railway will auto-redeploy

### Step 3: Configure Stripe Webhook

1. Go to Stripe Dashboard → Developers → Webhooks
2. Click "Add endpoint"
3. Endpoint URL: `https://your-app.up.railway.app/api/stripe/webhook`
4. Select events:
   - `checkout.session.completed`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
   - `invoice.payment_succeeded`
   - `invoice.payment_failed`
5. Copy the webhook secret
6. Update `STRIPE_WEBHOOK_SECRET` in Railway variables

### Step 4: Set Up Cron Job for Trial Expiration

**Option A: Railway Cron (Easiest)**

1. In Railway dashboard, click "+ New" → "Cron Job"
2. Schedule: `0 2 * * *` (daily at 2 AM)
3. Command:
   ```bash
   curl -X POST https://your-app.up.railway.app/api/cron/check-trials \
     -H "Authorization: Bearer YOUR_CRON_SECRET"
   ```

**Option B: External Service (cron-job.org)**

1. Go to https://cron-job.org
2. Create free account
3. Create new cron job:
   - Title: "WhaSales Trial Expiration"
   - URL: `https://your-app.up.railway.app/api/cron/check-trials`
   - Schedule: Daily at 2:00 AM
   - Add header: `Authorization: Bearer YOUR_CRON_SECRET`

## 🐛 Troubleshooting

### Build Fails with "Module not found: @upstash/redis"

**Solution:**
```bash
# Ensure package.json is committed
git add package.json package-lock.json
git commit -m "Add dependencies"
git push
```

### "CSRF_SECRET not set" Error

**Solution:**
1. Check Railway Variables tab
2. Ensure `CSRF_SECRET` is set
3. Redeploy

### Database Connection Timeout

**Solution:**
1. Check `DATABASE_URL` includes connection pool params:
   ```
   ?connection_limit=50&pool_timeout=20
   ```
2. Restart service

### WhatsApp Disconnects on Redeploy

**Solution:**
Railway provides persistent storage. Ensure:
1. Sessions stored in `/whatsapp_sessions` directory
2. This is part of the filesystem (it is by default)
3. May need to reconnect after major updates

### Prisma "Table doesn't exist"

**Solution:**
```bash
railway run npx prisma db push --force-reset
```

**⚠️ WARNING:** This will delete all data! Only use in development.

## 📈 Scaling on Railway

### Vertical Scaling (More Resources)

1. Go to Settings → "Resources"
2. Increase Memory/CPU
3. Railway will auto-restart

### Horizontal Scaling (Multiple Instances)

Railway doesn't support this directly. For 1000+ users, consider:
1. Upgrading server resources first
2. Using Railway's load balancer (Enterprise)
3. Or migrate to Kubernetes (overkill for most)
